# Plan: Local-first hosting + cross-device sync for MindSync

## Phase 0 — Back up the original project (MANDATORY, before any code changes)

**Goal:** preserve the current, working state of the repo in a `legacy/` folder so nothing in this plan can overwrite or destroy the original. If anything is needed later, it's all there.

**Steps:**
1. Create timestamped snapshot folder: `legacy/mindsync-original-<YYYYMMDD-HHMMSS>/`.
2. Copy the working tree into it, **excluding** regenerable/heavy paths:
   - `node_modules/` (deps reinstallable from package-lock.json)
   - `.next/` (build output; regenerated by `npm run build`)
   - `.git/` (history unaffected; nothing in this plan pushes git history)
   - `.stepcode/`, `demo/videos/` optional keeps — actually **include demo/videos** (large but original); exclude only the three above. Wait — verify sizes first; if videos/ is huge (>500MB), keep the copy lightweight and note the exclusion in the manifest instead of silently dropping it.
3. Write `legacy/mindsync-original-<timestamp>/RESTORE.md` containing:
   - the exact timestamp and source path
   - restore command (`xcopy`/`cp` back, or unzip) 
   - note of what was excluded and why (regenerable via `npm ci && npm run build`)
   - git HEAD hash if `.git` exists (rollback hook, even though .git isn't copied)
4. Verify the snapshot before proceeding: file count + total size of the copy vs. source (exclusions subtracted); spot-check that `src/`, `public/`, `docs/`, `package.json`, `next.config.ts`, `tools/` all exist in the snapshot.
5. Add `legacy/` to `.gitignore` (backup artifacts should not be committed into the repo).
6. **Gate:** no implementation file is created/modified until the verification in step 4 passes. This backup is itself a validation checkpoint.

**Note:** the only pre-plan mutations so far are `node_modules/` (was empty — now installed) and `.next/`/`public/sw.js` (build output). Both are regenerable; the snapshot captures the source tree as it stands now.

## Locked decisions
- Run locally on the user's PC via Docker (`docker compose up` = app + PocketBase).
- PocketBase (MIT, single binary) is the sync backend; **localStorage remains the local cache** — the app keeps working fully offline.
- Existing **Export/Import stays as the file backup** mechanism.
- Conflict policy: **per-record last-write-wins by `updatedAt`** (sufficient for single-user; documented in README).
- The StepFun API key is **never synced** (per-device privacy default).

## Key technical facts (verified during planning)
- PocketBase record IDs are capped at **15 chars**; current app IDs (`Date.now()-random`, ~23 chars) can't be PB record IDs → sync uses an **`appId` text field** and PB's own generated IDs. Legacy data syncs as-is, no ID migration.
- PocketBase has **no official Docker image** → use community image `adrianmusante/pocketbase` (official-binary Dockerfile documented as alternative).
- No Docker in this dev environment → compose is validated on the user's machine; sync logic is validated here by running the PocketBase Windows binary directly + two browser profiles.
- All store mutations funnel through Zustand + `db.*` (single choke point — verified by reading `useStore.ts`/`db.ts`).
- `fetchInitialData()` runs on app load (`page.tsx` useEffect) → hook for auto-sync.

## Quality gates (every task, as we go)

**Rule: no task is "done" until it passes its own verification + a review pass.** After each task:

1. **Mechanical checks** — `npm run build` and `npm run lint` must both pass after every code change (not just at the end). A change that breaks the build stops the line immediately.
2. **Task-specific checks** — each phase below has a "verify" line; run it before starting the next task.
3. **Subagent review as needed** — dispatch read-only `review`/`explore` subagents for anything non-trivial (sync merge logic, store changes, Docker config) before moving on; a fresh-context reviewer catches what the implementer's blind spots miss.
4. **Workflow-orchestrated adversarial verification at milestones** — after the sync layer (Phase 3) and at the end (post-Phase 6), run a workflow fanning out independent reviewers across dimensions:
   - sync correctness (LWW, tombstones, offline→converge, double-sync idempotency)
   - data safety (localStorage remains authoritative offline; no data loss on failed sync; import/export still works)
   - backward compatibility (legacy 23-char IDs, existing exports, PWA service worker behavior)
   - deployment (Dockerfile/compose correctness, env wiring, standalone output)
   Each finding gets adversarially re-verified before it's fixed; majority-refuted findings are dropped. Nothing is silently skipped.
5. **Fix-and-recheck loop** — any finding is fixed and its gate re-run before the next task starts.

## Phase 2 — PocketBase schema
Each collection stores the whole app record as JSON — no field-by-field mapping, stable as types evolve:
| Collection | Fields | Notes |
|---|---|---|
| `tasks` | `appId` (text, unique), `updatedAt` (text), `data` (json) | appId = Task.id |
| `goals` | same | appId = Goal.id |
| `snapshots` | same | appId = snapshot `date` (natural key) |
| `memories` | same | appId = AIMemory.id |
| `patterns` | same | appId = LearnedPattern.id |
| `settings` | same | single record, appId = `"preferences"` |
| `sync_deletions` | `entity`, `appId`, `deletedAt` | tombstones (delete propagation) |

- Collection rules: `@request.auth.id != ""` for list/view/create/update (single signed-in user).
- Verify: `tools/pb-setup.mjs` runs twice with no error (idempotent), 7 collections exist with correct fields + rules; a second user sees zero records (isolation check).
- `tools/pb-setup.mjs`: idempotent bootstrap via PB Admin API (superuser email/password from env) — creates the 7 collections with rules. Manual admin-UI steps documented as fallback.
- Auth: one PocketBase user (email/password) created via admin UI; SDK persists auth token in localStorage.

## Phase 3 — Sync layer (`src/lib/sync.ts`)
- `getClient(url)` → `pocketbase` SDK instance (`pocketbase` npm dep, ~small).
- `signIn(email, password)` / `signOut()` / `currentUser()`.
- `syncNow()`:
  1. **Push** — per collection, `getFullList()`, build Map by appId; for each local record, if remote missing or `local.updatedAt > remote.updatedAt` → create/update (payload `{appId, updatedAt, data}`).
  2. **Push deletions** — flush local deletion queue (`mindsync_sync_deletions` in localStorage) into PB `sync_deletions`, clear queue.
  3. **Pull deletions** — fetch `sync_deletions` where `deletedAt > lastSyncedAt`; apply locally.
  4. **Pull changes** — for each remote record: missing locally or `remote.updatedAt > local.updatedAt` → merge into store + localStorage. Snapshots/patterns/memories same treatment; `settings` = whole-object replace if newer.
  5. Persist `mindsync_last_sync`.
- Merge helpers apply to both Zustand state and `db.*` (localStorage) so offline-first cache stays authoritative locally.
- **Verify:** full two-profile test — A edits → sync → B receives; B edits → sync → A receives (LWW); delete on A → tombstone removes on B; re-running sync with no changes is a no-op; PB stopped → sync fails silently, app unaffected.

## Phase 4 — Data model touch-ups (minimal ripple)
- `types.ts`: add `updatedAt?: string` to Task, Goal, DailySnapshot, AIMemory, LearnedPattern.
- `db.ts`: `saveTask/saveGoal/saveSnapshot/addAiMemory/addLearnedPattern/savePreferences` auto-stamp `updatedAt = new Date().toISOString()` on write; add deletion-queue helpers (`queueDeletion`, `getDeletionQueue`, `clearDeletionQueue`).
- `useStore.ts`: stamp `updatedAt` in all mutators (`addTask, moveTask, updateTask, deleteTask, clearCompletedTasks, addGoal, editGoal, toggleGoal, deleteGoal, addMemory, addLearnedPattern, updatePreferences`); delete paths enqueue tombstones.
- **Verify:** `npm run build` + `npm run lint`; new records carry `updatedAt` in localStorage; existing legacy records (no `updatedAt`) treated as "never synced" and sync without corruption.

## Phase 5 — Sync UI + auto-sync
- `SettingsTab.tsx`: "Cloud Sync" section (in the Data Lab modal / Settings): PocketBase URL (prefilled `NEXT_PUBLIC_PB_URL`), email, password, **Sign in / Sync now / Sign out**, last-synced timestamp + status line. New `SyncPanel` component; store actions: `signIn, syncNow, signOut`.
- Auto-sync: `fetchInitialData()` calls `syncNow()` when an auth token exists (silent, non-blocking; offline → no-op).
- Stretch (only if trivial): `pb.collection('tasks').subscribe('*', ...)` for live cross-device updates.

## Explicitly out of scope
- Multi-user accounts, cloud hosting migration (VPS/Coolify later — compose file ports over unchanged).
- Syncing `stepfunConfig` (API key stays per-device).
- Real-time subscriptions in v1.

## Validation
0. **Backup gate (Phase 0):** snapshot exists in `legacy/`, file counts verified, `.gitignore` updated — before writing any code.
1. `npm run build` + `npm run lint` must pass.
2. Run PocketBase Windows binary locally, `node tools/pb-setup.mjs` creates collections; create test user.
3. Two browser profiles ("device A/B", Docker app on :3000): sign in on both, add tasks on A, sync, verify appear on B; edit on B, sync, verify LWW on A; delete on A, sync, verify tombstone removes on B.
4. Offline test: disable PB (stop binary) → app still fully usable from localStorage; restart → sync converges.
5. `docker compose up --build` tested on user's machine (documented; no Docker in dev env).
6. **Workflow adversarial review (milestone gate):** after Phase 3 and once more post-Phase 6, run a workflow fanning out independent reviewers across the four dimensions (sync correctness, data safety, backward compatibility, deployment), adversarially re-verify every finding, and fix + re-run the affected gates before declaring any phase complete.

## Risks
- npm blocked install scripts for `sharp`/`unrs-resolver` locally (allow-scripts) — only affects image optimization; build passes without them. Docker install runs scripts normally.
- LWW assumes timestamps are sane (same machine clock family); acceptable for single user.
- PB version pinning: community image `latest` → pin a version at implementation time.
